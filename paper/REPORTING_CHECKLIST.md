# Reporting checklist

Aligned with the Nature Portfolio Reporting Summary and the life-sciences reporting checklist.
Every claim in `CLAIMS.md` must pass every line. Reviewers tick it in the PR.

## Statistics
- [ ] n stated for every result, and what n is (datasets; never edges, cells or genes as units)
- [ ] exact test named (paired t via `compare_units` unless the record declares otherwise), two-sided
- [ ] effect size (mean paired difference) with 95% CI, not only a p-value
- [ ] multiple-comparison correction named (Holm) with the full declared family and its size
- [ ] "significant" used only inside the declared family; unresolved is reported as unresolved, not as "no difference"
- [ ] exploratory vs confirmatory stated; exploratory results not presented as findings
- [ ] exclusions stated with the rule that was fixed before the run
- [ ] negative and null comparisons from the same family reported alongside the positive ones

## Data
- [ ] every dataset in `experiments/datasets.tsv` with source, version, sha256; licence checked
- [ ] train/selection vs evaluation split stated (reference halves, seed) and never crossed
- [ ] reference networks named with version; no circularity (a prior used by a model is not the evaluation reference)

## Software and reproducibility
- [ ] commit hash and environment (lock file, Python version, extra packages) in the record
- [ ] seeds recorded
- [ ] numbers produced by scripts; table/figure regenerated by `python paper/make_figures.py`
- [ ] reproduced by a second person from the record alone (record section 4)

## Availability
- [ ] code and data availability statements in `AVAILABILITY.md` up to date
