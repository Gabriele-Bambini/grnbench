# EXP-20261001-LD-1: Exploratory contextual stress and complete real-data validation

## 1. Registration (before the run)

- type: **exploratory**. This run validates new simulator/runner machinery and estimates stress
  curves; it cannot support a headline or paper claim without a separately registered
  confirmatory rerun.
- owner: LD (agent-run)   issue: #23   registered: 2026-10-01
- implementation: issue #22, decision D-019. Issue #21 (versioned CollecTRI/DoRothEA snapshots)
  was unresolved at registration, so the real-data part records the exact current CollecTRI
  SHA256 values in `RUN_CONFIG.json` and is not treated as comparable to older reference
  snapshots. The team approved D-020 after execution; it governs future registered snapshots.
- question: does the context-specific simulator and status-aware benchmark complete every planned
  synthetic and approved real-data task without silent omissions, and at what declared severity
  does each model first lose recovery or operability?
- primary endpoints (diagnostic, not confirmatory): (a) task completeness by terminal status;
  (b) AUPRC ratio on the held-out planted truth, macro-averaged over cell types, for the `auto` arm;
  (c) generated statistical, half-clean and operational breaking points. Secondary: EPR; baseline
  and rules arms; real-data reference recovery and refusal/error counts.
- units of analysis: one simulated dataset (scenario x seed; planned n = 740) for synthetic
  summaries; one biological dataset (expected n = 40) for the real-data audit. Edges, cells and
  contexts are never treated as independent units.
- synthetic datasets: immutable manifest generated by
  `engine_bench.py plan --stress-grid --stress-seeds 5`: four shared-edge regimes (1.00, 0.75,
  0.50, 0.25) x [clean + 8 one-factor stressors x 4 non-baseline levels + 4 mixed levels] x
  seeds 0-4 = 740. Stressors/levels are fixed in D-019 and `STRESS_FACTORS`.
- real datasets: every task generated from the existing approved `~/grnbench_data` setup root by
  `real_bench.py plan`: 30 CELLxGENE datasets, PBMC3k filtered/raw, Paul15 and seven BEELINE inputs
  (expected n = 40). No download, deletion or replacement is part of this run. The BEELINE inputs
  are expected refusals because they are normalized rather than raw counts.
- exclusion/accounting rules (fixed now): no outlier removal and no silent exclusion. Every
  manifest task must end as `completed`, `expected_refusal` or `permanent_error`; missing or
  `transient_error` rows make the final report refuse. A row-level exception is tried at most twice
  and then retained as `permanent_error`. A missing model score remains visible and defines an
  operational break. Expected BEELINE refusals are terminal successes. No task is replaced.
- comparisons: exploratory/descriptive only: auto/rules/baseline arms and four models. There is no
  confirmatory comparison family and no significance verdict. Per-level 95% t intervals across the
  five simulator seeds are diagnostics, not registered hypothesis tests.
- breaking-point rules: statistical = first stress level whose 95% t interval for AUPRC ratio no
  longer lies wholly above random (1); half-clean = first level whose mean is <= 50% of the clean
  mean in the same shared-edge regime; operational = first level with any missing model score.
- models: `pearson_signed`, `clr`, `grnboost2`, `regdiffusion`. Expensive models are evaluated only
  on distinct baseline/rules/auto candidates and never select a pipeline on the evaluation truth.
  Exploratory compute parameters: GRNBoost2 `n_estimators=100`; RegDiffusion `n_steps=100`, CPU.
  Motif models are excluded so unresolved issue #21 does not add a second reference-like input.
- seeds: scenario seeds 0-4; union-truth split seed = scenario seed; score-cell subsample seed 0;
  GRNBoost2 seed 42; RegDiffusion seed 0. Shared edges are split before context expansion, so the
  same shared edge can never enter selection for one type and evaluation for another.
- primary comparison: none (exploratory validation).
- smallest effect that matters: none declared.

## 2. How it runs

- code: clean commit on branch `ld/contextual-stress-bench`; `hpc/hpc.sh sync` writes its hash to
  `GIT_COMMIT`, and each job copies that into `CODE_COMMIT`. The task SHA256 and score-affecting
  options are pinned separately in `tasks.json` and `RUN_CONFIG.json`.
- environment: Bocconi HPC conda env `grnbench`, Python 3.11,
  `requirements/lock-py311.txt` plus its pinned RegDiffusion/CPU-torch header line via
  `WITH_TORCH=1 bash hpc/setup_env.sh`.
- machine: Bocconi HPC, partition/QOS `stud`, one job at a time, 8 CPUs, 32 GB, 24 h. Work files use
  `~/gb_tmp`, not compute-node `/tmp`; resubmission uses the identical command and output folder.
- synthetic commands (`O=~/gb_runs/EXP-20261001-LD-1/synthetic`):
  ```
  python benchmarks/engine_bench.py plan --stress-grid --stress-seeds 5 --out $O/tasks.json
  sbatch --time=24:00:00 --export=ALL,OUT=$O,TASKS=$O/tasks.json,CHUNK=100000,MODELS=pearson_signed+clr+grnboost2+regdiffusion,KEEP_ARTIFACTS=1,MAX_ATTEMPTS=2,TMPDIR=$HOME/gb_tmp hpc/engine_bench.sbatch
  python benchmarks/engine_bench.py report --out $O
  ```
  `KEEP_ARTIFACTS=1` retains exactly 12 pre-declared sentinels outside git: clean, extreme depth
  and extreme mixed (seed 0) in each shared-edge regime.
- real commands (`O=~/gb_runs/EXP-20261001-LD-1/real`):
  ```
  python benchmarks/real_bench.py plan --data-root ~/grnbench_data --out $O/real_tasks.json
  sbatch --time=24:00:00 --export=ALL,OUT=$O,SCRIPT=benchmarks/real_bench.py,TASKS=$O/real_tasks.json,REFS=$HOME/grnbench_data/references,CHUNK=100000,MODELS=pearson_signed+clr+grnboost2+regdiffusion,KEEP_ARTIFACTS=1,MAX_ATTEMPTS=2,TMPDIR=$HOME/gb_tmp hpc/engine_bench.sbatch
  python benchmarks/real_bench.py report --out $O --tasks $O/real_tasks.json --tasks-for-viz $O/real_tasks.json
  ```
- results: large work and artifacts under `~/gb_runs/EXP-20261001-LD-1/`; small generated reports,
  terminal rows, portable manifests and hashes will go to
  `benchmarks/results/EXP-20261001-LD-1/` after completion.
- report inputs: `~/gb_runs/EXP-20261001-LD-1/synthetic` and
  `~/gb_runs/EXP-20261001-LD-1/real`.
- report input: `benchmarks/results/EXP-20261001-LD-1/real`
- status at registration: not submitted. Local pre-run validation completed on one historical
  shared-network task, one 75%-shared context-specific task and one small GRNBoost2 task; these are
  software smoke tests only and are not experiment results.

## 3. Results (filled by scripts, not by hand)

- status: **done**. Both phases are completely accounted for; this remains exploratory and does

- headline: the complete synthetic grid identifies controlled degradation under low depth, few
  cells and mixed stress, but the real-data audit provides no evidence that the automatic cleaning
  is consistently better than the baseline. The automatic and baseline pipelines are usually
  exactly tied on the real datasets that both score.
- all declared comparisons: none. Tables labelled configured/declared by the shared legacy report

- synthetic verdict: `COMPLETE.json` confirms 740 planned / 740 completed, zero missing,
  retryable, duplicate, invalid or permanent-error rows, and no run-config mismatch. All four
  requested models have finite auto/rules scores on all 740 datasets. Baseline scores are available
  on 700; the 40 missing cases are retained at extreme depth and mixed level 4. No requested model
  has an operational break in the auto arm. Half-clean breaks are reached most consistently under
  depth (moderate to extreme), cell-count reduction (severe or extreme) and mixed stress (levels
  1-3); CLR and RegDiffusion also reach it under extreme ambient contamination in most regimes.
