# EXP-20261004-LM-1: On the genes a candidate shares with the baseline, does it still beat the baseline?

## 1. Registration (before the run)

- type: **exploratory**. It decides which gene-set-changing candidates (HVG size, gene filter,
  context scope, metacells) deserve a confirmatory test; it supports no claim on its own.
- owner: LM (agent-run)   issue: #47   registered: 2026-10-04
- why: in EXP-20261002-LM-2 and EXP-20261003-LM-1 every candidate was scored on its own TF x gene
  universe, so candidates that change the gene set (`hvg=tf_plus_2000` above all) were compared
  with the baseline on different edge sets. About 70% of the "all candidates" selection gain came
  from them. On one dataset (smoke run of this script) the `hvg=tf_plus_2000` gain fell from +0.016
  on its own universe to -0.002 on the genes it shares with the baseline, while `metacells` kept
  +0.126 of +0.133.
- question: per variant, the mean over datasets of (variant - baseline) AUPRC ratio when BOTH are
  scored on TF x (genes of the variant AND genes of the baseline), next to the own-universe
  difference of EXP-20261002-LM-2.
- design: `benchmarks/candidate_study.py` with pairwise shared-gene scoring (`pair_eval_*`,
  `pair_base_eval_*`); condition `clean` only; same candidates, seeds and reference halves as
  EXP-20261002-LM-2. Inference runs once per candidate; the baseline's edges are re-evaluated on
  each candidate's shared genes.
- datasets: the 20 development datasets of EXP-20261002-LM-2 (`~/grnbench_data_lm1`), so the
  own-universe numbers can be checked against that run. Registered CollecTRI snapshot.
- unit: dataset (n = 20). Edges, cells and contexts are never units.
- endpoints (descriptive, no p-values): per variant, mean and wins/losses of the shared-gene
  difference and of the own-universe difference; the "all candidates, with reference" selection
  rule judged on shared genes.
- exclusions: as EXP-20261002-LM-2 (fewer than 50 reference edges: not scored; a failing candidate
  is left out of its own comparison only).
- check fixed now: the own-universe `eval_mean` of every candidate must equal EXP-20261002-LM-2's
  `clean` rows (the scoring path is shared); any difference is reported before anything else.
- seeds: degradation seed 0, reference split seed 0, adapter defaults.

## 2. How it runs

- code: branch `lm/common-universe` at the commit that adds this file; synced to a separate cluster
  checkout `~/grnbench-cu`; `CODE_COMMIT` copied into the results.
- commands (`D=~/grnbench_data_lm1`, `O=~/gb_runs/EXP-20261004-LM-1`):
  ```
  python benchmarks/data_manifest.py $D --check experiments/datasets.tsv          # must exit 0
  python benchmarks/candidate_study.py plan --data-root $D --out $O/tasks.json --conditions clean
  sbatch --time=12:00:00 --export=ALL,REPO_DIR=$HOME/grnbench-cu,OUT=$O,SCRIPT=benchmarks/candidate_study.py,TASKS=$O/tasks.json,REFS=$D/references,CHUNK=100000,JOBS=6,TMPDIR=$HOME/gb_tmp_cu hpc/engine_bench.sbatch
  python benchmarks/candidate_study.py report --out $O
  ```
- machine: Bocconi HPC, QOS `stud`, 8 CPUs, 32 GB; 20 tasks, about 1-2 h.
- results: `benchmarks/results/EXP-20261004-LM-1/`.

  the same genes, no single cleaning change beats the fixed baseline by more than about 0.01 AUPRC
  ratio. The HVG-2000 gain and almost all of the reference-based selection gain came from the
  larger edge universe. Metacells, per-type contexts, batch correction and Pearson residuals still
  lower recovery.

## 5. Next (decided 2026-10-04)

- No change to the HVG default and no confirmatory test of gene-set-changing candidates: there is
  no gain on shared genes to confirm.
- For the product this means the fixed baseline is close to the best available pipeline on curated
  data. The engine's measured value is in avoiding harm (D-021, the low-depth refusals the
  adaptive candidates avoid) and in explaining its choices, not in raising recovery there.
