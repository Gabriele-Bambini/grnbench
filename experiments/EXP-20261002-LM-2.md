# EXP-20261002-LM-2: Where does cleaning help on real data, and which selection rule finds it?

## 1. Registration (before the run)

- type: **exploratory**. It maps where cleaning choices change GRN recovery on real data and
  calibrates selection rules; any change it suggests to the engine needs a confirmatory run on
  datasets not used here.
- owner: LM (agent-run)   issue: #28   registered: 2026-10-02
- why: in EXP-20260925-LM-1, EXP-20260925-LM-2 and EXP-20260926-LM-1 (curated CELLxGENE data) the
  best of the engine's candidates beats the fixed baseline by only 0.01-0.03 AUPRC ratio, and the
  reference-free selection (`auto_noref`) loses to the baseline (-0.12, -0.17, -0.12 mean;
  worse in 11/20, 9/12, 11/20 datasets), mostly by choosing `batch=center_per_batch`. Two
  questions follow: is there headroom outside the engine's candidate set or on less clean data,
  and which reference-free rule would not lose to the baseline?
- question: for each degradation condition, how far do the engine's choice, the reference-free
  choice and every one-change variant of the baseline move the AUPRC ratio on the CollecTRI
  evaluation half, relative to the baseline?
- design: 20 datasets x 7 conditions = 140 tasks (`benchmarks/candidate_study.py`).
  Conditions, applied to the integer counts with seed 0: `clean`; `depth_30`, `depth_10` (binomial
  thinning, keep 30% / 10%); `ambient_20` (Poisson ambient counts = 0.2 x library from the
  dataset's own mean profile); `doublets_20` (20% added doublets, sums of two cells of different
  cell types when labelled); `damaged_15` (15% of cells keep 30% of non-mitochondrial counts);
  `mixed` (doublets, then ambient, then depth 30%). Every condition, `clean` included, runs on a
  written copy, so they share one code path.
- candidates per task: the engine's own (`max_candidates=4`, as in `real_bench`), the baseline
  (`engine_bench.BASELINE`), and the baseline with one change each (`VARIANTS` in the script:
  cell QC mad / mad_per_batch, scrublet doublets, QC-gene filter, per-cell-type and selected-type
  context, Pearson residuals, center-per-batch and ComBat batch, metacells, HVG 500 / 2000).
  Options unavailable on the cluster are skipped and listed in each row.
- unit of analysis: dataset within condition (n = 20 per condition). Edges, cells and contexts are
  never units.
- endpoints (descriptive): `eval_mean` (mean AUPRC ratio of pearson_signed, spearman_signed and clr
  on the evaluation half) per candidate; per condition: baseline, engine auto (with the selection
  half), engine auto without reference, oracle over the engine's candidates, oracle over all
  candidates, and each variant's paired difference from the baseline with its count of wins.
  Selection rules are compared offline on the same table.
- datasets: the 20 CELLxGENE datasets of EXP-20260925-LM-2 / EXP-20260926-LM-1
  (`~/grnbench_data_lm1`, checked with `data_manifest.py --check` before the run). They are
  already used, which is acceptable for an exploratory map and is why any engine change it
  motivates is confirmed on a fresh set.
- exclusions (fixed now): datasets with fewer than 50 reference edges are not scored; a failing
  candidate is recorded with its error and left out of that candidate's means only; no other
  exclusion.
- comparisons: none confirmatory, no p-values. Summaries are means of paired differences and win
  counts.
- seeds: degradation seed 0; reference split seed 0; the adapters' default seeds.
- validation before registration (not a result): on one dataset of this set
  (`primary-motor-cortex__9b686bb6`) the `clean` task reproduced EXP-20260926-LM-1's baseline
  (0.99642 vs 0.99643), auto (1.0040 vs 1.0038) and the same auto and auto-without-reference
  choices.

## 2. How it runs

- code: branch `lm/candidate-study`; `hpc/hpc.sh sync` writes the commit to `GIT_COMMIT`; the job
  runs from a separate cluster checkout `~/grnbench-cs` via `REPO_DIR` and copies `GIT_COMMIT`
  into the results as `CODE_COMMIT`.
- environment: conda env `grnbench`, Python 3.11, `requirements/lock-py311.txt`.
- commands (`D=~/grnbench_data_lm1`, `O=~/gb_runs/EXP-20261002-LM-2`):
  ```
  python benchmarks/data_manifest.py $D --check experiments/datasets.tsv      # must exit 0
  python benchmarks/candidate_study.py plan --data-root $D --out $O/tasks.json
  sbatch --time=24:00:00 --export=ALL,REPO_DIR=$HOME/grnbench-cs,OUT=$O,SCRIPT=benchmarks/candidate_study.py,TASKS=$O/tasks.json,REFS=$D/references,CHUNK=100000,TMPDIR=$HOME/gb_tmp_cs hpc/engine_bench.sbatch
  python benchmarks/candidate_study.py report --out $O
  ```
  Resumable: a resubmission with the same command runs only the missing tasks.
- machine: Bocconi HPC, QOS `stud`, 8 CPUs, 32 GB, 24 h. Smoke timing: about 20 min per task on
  a 1,705-cell dataset on the laptop; expect 10-20 h for 140 tasks.
- results: `benchmarks/results/EXP-20261002-LM-2/` (rows, `candidates.csv`, `SUMMARY.md`).

- findings (descriptive, exploratory):
  1. Little headroom. Even the best of all candidates beats the baseline by 0.041-0.084 (mean of
     each arm over its own tasks), and the degradations barely move the baseline (1.33-1.39)
     except where it stops: the fixed QC gates
     refuse 7/20 datasets at 10% depth (1/20 at 30%, 1/19 mixed), where the engine's adaptive
     candidates still produce a network.
  2. Without a reference, the engine's choice loses to the baseline in every condition (-0.085 to
     -0.220; worse in 11-15 of the datasets per condition, 5 of 13 at 10% depth). Dropping the
     batch term helps a little in 5 of 7 conditions but still loses (-0.088 to -0.220);
     searching all candidates without a reference is worse (`SUMMARY.md`, selection rules).
  3. The rules-only (`recommended`) pipeline is 0.044-0.127 below the baseline in every condition. Single
     changes that lower recovery in every condition: Pearson residuals (-0.26 to -0.33), batch
     centering (-0.21 to -0.28), ComBat (-0.20 to -0.28), metacells (-0.12 to -0.19),
     per-cell-type (-0.06 to -0.10) and selected-type contexts (-0.05 to -0.10), HVG 500 (-0.03
     to -0.06). HVG 2000 is the only consistent gain (+0.010 to +0.037); the rest stay within
     -0.023 and +0.017.
  4. With the reference, choosing among all candidates gains +0.023 to +0.069 (wins 8-17 per
     condition), but mostly by picking `hvg=tf_plus_2000` (11/20 on clean), which is scored on a
     larger TF x gene universe. Among candidates that keep the baseline's gene set the gain on
     clean data is +0.019 [+0.002, +0.036] (`CONFIRM_FAMILY_on_development_set.md`).
- how rules pick (method note): `rule_choice` and `_rule_pool` skip candidates whose evaluation
  score is missing (a failed or refused pipeline), so a rule falls back to its next-best
  candidate instead of returning a failed network. This uses outcome information; on these rows
  it changed 0 picks for the shipped reference-free rule and for the gene-set-preserving rule
  (independent review of #38), and it can only flatter the rule being tested.
- consequence: EXP-20261003-LM-1 tests, on 20 datasets not used here, (H1) baseline > the shipped
  reference-free choice and (H2) gene-set-preserving reference-based screening > baseline. A fair
  comparison of gene-set-changing candidates needs scoring on a common gene universe (not done).
- deviations from section 1: the report gained the selection-rule table and the baseline-failure
  count after registration (report code only, before any row existed for the first and before the
  run ended for the second).
