# EXP-20261003-GB-1: How much of the motif-prior lift for Pearson (C4, C6) needs target identity? (stage 1 of the audit's sensitivity analysis)

## 1. Registration (before the run)

- type: **exploratory**. It can qualify the wording of the dated caveat on C4 and C6; it cannot
  create a headline claim or change a claim status.
- owner: GB (agent-prepared)   issue: #52   registered: 2026-10-05 (the pushed commit of this file = the pre-registration;
  drafted from 2026-10-03, revised after an agent review of the draft on 2026-10-05, section 2)
- follows: the 2026-09-27 audit (`audit/2026-09-27/AUDIT.md` sections 3 and 6, design in
  `audit/2026-09-27/proposal/PLAN.md`; branch `lm/audit-2026-09-27`, PR #45) and issue #41, where
  LM assigned this analysis to GB and shared the kept artifacts. The audit found two design effects
  that raise the pooled AUPRC ratio of `X_motif` without any information on which target a TF
  regulates: (1) TF-level reweighting, because `cistarget.motif_ranks` takes the best rank over all
  of a TF's motifs; (2) database membership, because a gene absent from the cisTarget rankings is
  tied at the worst rank, and many such genes (Ensembl IDs without a symbol) can never be
  CollecTRI positives.
- question: on the registered C6 and C4 runs, how much of the pooled AUPRC-ratio lift of
  `pearson_motif` over `pearson_signed` needs the motif prior's target identity, and how much is
  reached by the two design effects alone, or by a TF-generic gene propensity (the prior knowing
  which genes are regulated, not by which TF)?
- hypothesis (directional expectations, exploratory): T1, the real prior beats a random
  within-database target assignment that keeps its TF-level and database structure; T2, the real
  prior improves within-TF ranking on the restricted universe where neither design effect can act;
  T3, on that universe it also beats a TF-generic gene propensity built from the other TFs' motifs.
- scope: **stage 1 only**, the Pearson family (`pearson_signed` base, `pearson_motif` combined;
  `motif_prior` only for C4's calibration). Tier B of PLAN.md: `pearson_signed` is recomputed
  exactly from each kept `processed.h5ad` (closed form, no seed); no model is refit and no
  expression data is downloaded. **Stage 2 (RegDiffusion, GRNBoost2) is out of scope** until the audit's GRNBoost2
  calibration gap (AUDIT.md section 6: the recombined `grnboost2_motif` missed its row by 0.19-0.31
  on a mock) is fixed and validated against the kept C5/C6 artifacts. Stage 2 will be a dated
  amendment or a new record, registered before it runs. The script refuses stage-2 models.

- metrics (PLAN.md section 2), each for the base, the real prior and every control:
  - `pooled`: the registered AUPRC ratio on the CollecTRI evaluation half, universe U = regulators
    x genes of the kept context (self pairs excluded), missing edges tied at the bottom
    (`evaluate_ranking` with `universe=`); EPR for base and real (descriptive).
  - `macro`: mean over TFs of the within-TF AUPRC ratio (each TF's row of U, same ranking); only
    TFs with at least `MIN_POS_TF` = 5 evaluation positives in the row count.
  - `pooled_T` / `macro_T`: U restricted to U' = pairs whose target is in the cisTarget rankings
    (any database) and labelable (a target of any TF in the registered `collectri_<organism>.tsv`).
  - `pooled_R` / `macro_R`: U'' = U' restricted to TFs with at least one annotated motif present
    in the databases (K >= 1).
  - dataset value = mean over the dataset's contexts with a finite value (as `score_models`).
- controls (each a motif matrix M' rank-producted with the same base edges; M = the registered
  `cistarget.motif_ranks`; W = the worst rank, the tie value of motif-less TFs and absent genes):
  - `perm_db` (**primary null**): for seed s, each TF's own in-database values are re-assigned to
    its in-database genes in the order of a key u = hash(s, TF, gene) (64-bit blake2b keys of the
    upper-case names mixed by splitmix64; `keyed_order` in the script); seeds 0-99. It keeps the
    TF-level distribution and the database mask exactly and destroys target identity. Because u
    does not depend on the dataset, every dataset orders the genes it shares with another the same
    way: one seed is one random database shared by all datasets, as the real database is. Value =
    mean over the 100 seeds.
  - `perm_all`: the same keyed re-assignment over all genes, seeds 0-99 (also destroys the mask).
  - `tf_mean`: constant row, the TF's mean rank over in-database genes (W if K = 0).
  - `tf_kexp`: constant row (W + 1) / (K + 1) (W if K = 0).
  - `tf_presence`: constant row, 1 if K > 0, else W.
  - `db_only`: 1 if the gene is in a database, else W, for every TF.
  - `worst_tie`: 1 where M < W, else W (the real prior's own tie set).
  - `tfmean_db`: the TF mean on in-database genes, W elsewhere (everything but target identity).
  - `gene_tf` (**gene-propensity null**, added after the review): for each TF with K >= 1, the
    gene propensity is the leave-one-out mean of M over the other TFs with K >= 1 on each
    in-database gene; the TF keeps its own sorted in-database values (TF-level distribution, mask
    and tie set of the real prior, exactly) and assigns them to genes in propensity order. W
    elsewhere. Everything but TF-specific target identity. (With a single TF with K >= 1 the
    propensity is that TF's own row, so `gene_tf` equals the real prior and T3 cannot pass.)
  - `gene_mean` (descriptive): that leave-one-out mean itself as the TF's row on in-database genes.
  - built-in checks that must hold exactly (checked by the script on every context, a violation is
    a code error; also shown on mocks by `tests/test_motif_sensitivity.py`): constant-row controls
    (`tf_mean`, `tf_kexp`, `tf_presence`) give zero lift on every macro metric; `tf_presence`,
    `db_only`, `worst_tie` give zero lift on `pooled_R` and `macro_R`; `tfmean_db` gives zero lift
    on `macro_R`. The `worst_tie` check is only applicable when no in-database gene has the worst
    rank for a TF with a motif (it can happen when the two databases do not share gene columns);
    the report counts the contexts where it was not applicable.
- declared tests (stage 1, per set, auto arm):
  - T1: `pooled`(pearson_motif) > `pooled`(perm_db).
  - T2: `macro_R`(pearson_motif) > `macro_R`(pearson_signed).
  - T3: `macro_R`(pearson_motif) > `macro_R`(gene_tf).
  - paired t over datasets, one one-sided test per direction (as `compare_units` computes them),
    `compare_units` for each test (two-sided 95% interval of the mean paired difference), Holm
    (`holm_adjust`) over **the family of each set: 1 pair (pearson_motif vs pearson_signed) x 3
    tests x 2 directions = 6 directed hypotheses**, alpha 0.05. The two sets are two separate
    families of 6. A test is supported if p_Holm(A > B) < 0.05, its reverse if p_Holm(B > A) <
    0.05; otherwise unresolved (not equivalence). A test with fewer than 3 analysed datasets is
    not run and the family shrinks by its 2 hypotheses; the report prints the family size.
  - arm: **auto** (the engine's screened choice, as registered for C4 and C6) is primary; the
    baseline arm gets the same three tests as a secondary family of 6, reported, sign agreement
    only. In the committed rows the auto pipeline is the baseline pipeline on 13/20 C6 and 12/20 C4
    datasets, so the baseline arm largely repeats the primary; the report prints this count.
- comparison family: the 6 directed hypotheses above, per set and arm. Everything else is
  descriptive: every control x metric x arm against the base (`compare_units`, Holm over the two
  directions of that row only), the share of the real lift taken by each control (bootstrap over
  datasets, 2,000 draws, seed 0), and per-context diagnostics (motif-less TFs, genes outside the
  databases, Ensembl-ID genes, universe share and gold edges in the worst-rank tie, sizes of U'
  and U'' and their gold edges, TFs entering `macro` and `macro_R` (at least 5 positives),
  Spearman(K, gold targets per TF)).
- robustness condition on T1 (fixed now): the cisTarget databases and the reference are the
  same object for all datasets, so the dataset-to-dataset variance of T1 does not include the
  chance of one database realization. The report gives the permutation rank of the set mean of the
  real prior among the 100 set means of the keyed permuted priors (one shared random database per
  seed, see `perm_db`), p_perm = (1 + #{seeds >= real}) / 101.
  **p_perm < 0.05 is a co-condition of the strongest verdict:** "supports target-level evidence"
  needs it (rule 3 below). If T1 is supported by the t test but p_perm >= 0.05, or p_perm cannot be
  assessed (too few seeds to reach 0.05), that verdict becomes "mixed" and is quoted with "T1 not
  robust to the realization of the one shared database". In every other case p_perm is reported
  only. (GB, 2026-10-04, before registration: the more cautious reading.) Why the keyed
  permutation (review of the draft, 2026-10-05): with a fresh permutation per context, a seed is
  not one shared database, the permuted set means vary too little and p_perm is anti-conservative.
  In a simulation with no motif information and a fixed reference, p_perm < 0.05 occurred in 21
  of 200 realizations with the per-context permutation and 3 of 200 with the keyed one (12
  datasets, 20 seeds; the script's keyed permutation is identical to the simulated one). With 100
  seeds the smallest p_perm is 1/101; near the 0.05 cut the condition has limited power (at a true
  p of 0.04, about 63% of runs pass), which errs towards "mixed".
- decision rule (per set, auto arm; PLAN.md section 5 with an explicit precedence, the more
  cautious row winning where PLAN.md's rows overlap). Quantities are means over the analysed
  datasets: L = pooled(real) - pooled(base) (must reproduce the registered lift, gate 2);
  D = pooled(real) - pooled(perm_db); L_art = pooled(tfmean_db) - pooled(base);
  L_gene = pooled(gene_tf) - pooled(base).
  0. a code check failed, or gate 2 failed with every dataset through gate 1: **not
     interpretable** (no other row is read).
  1. L <= 0 on the analysed datasets: **inconclusive** (no lift to decompose).
  2. T1's reverse supported (a random assignment beats the real prior) or T2's reverse supported
     (the real prior lowers within-TF ranking where neither design effect can act): **consistent
     with design effects only**.
  3. T1 and T2 supported: **supports target-level evidence** if T3 is supported, D >= 0.5 L,
     L_art < 0.5 L, L_gene < 0.5 L and p_perm < 0.05 (robustness condition above); otherwise
     **mixed**, and the report names every condition that failed. If T3 or L_gene fails, the
     verdict line adds "consistent with a TF-generic gene propensity".
  4. exactly one of T1, T2 supported: **mixed** if L_art >= 0.5 L, otherwise **inconclusive**.
  5. neither supported: **consistent with design effects only** if L_art >= 0.5 L, otherwise
     **inconclusive**.
  The 0.5 L cuts use point estimates. The report prints D/L, L_art/L and L_gene/L with bootstrap
  95% intervals over datasets (2,000 draws, seed 0); D/L can exceed 1 when permutation noise puts
  `perm_db` below the base. The shares and components (`tf_mean`, `tf_presence`, `db_only`,
  `worst_tie`, `gene_mean`, `gene_tf`) name the dominant effect and never decide.
  Differences from PLAN.md section 5, all deliberate: (i) an explicit precedence; (ii) rule 4
  calls "T1 supported, T2 not, L_art >= 0.5 L" mixed where PLAN.md calls it artifact, because a
  supported T1 means that a random target assignment loses part of the lift, which contradicts
  "design effects only"; (iii) T2's reverse joins T1's in rule 2; (iv) rule 3 adds T3, L_gene and
  the robustness condition, after the review showed on a mock that a TF-generic gene propensity
  (no TF-specific information) passes T1 and T2 and was called target-level (n = 20, L = +0.19,
  T1 and T2 p_Holm <= 0.005).
- secondary agreement (fixed now): next to the auto arm's verdict the report prints whether
  EPR(real) - EPR(base) has the sign of L, and whether the baseline arm's L and T1-T3 mean
  differences have the auto arm's signs. A disagreement is named in the verdict line ("Secondary
  checks ... DISAGREE: ...") and never changes the verdict.
- what each outcome means for the caveat on C4/C6 (the claims' registered numbers stand in every
  case: gate 2 reproduces them by design; no claim status changes):
  - supports target-level evidence: the dated caveat can be narrowed for Pearson on that set, to
    say the lift is mainly target-level. RegDiffusion and GRNBoost2 (C5, C6) keep the caveat until
    stage 2.
  - mixed: the caveat stays and is reworded to name the components with their sizes from the
    report; when T3 or L_gene failed it also says that the lift is consistent with a TF-generic
    gene propensity (the prior ranks genes that many TFs regulate, not the targets of each TF).
  - not interpretable: nothing about the caveat changes until the cause is fixed and recorded.
  - consistent with design effects only: the caveat is strengthened. C4/C6 may say that the motif
    prior raises the pooled AUPRC ratio, not that it is sequence evidence at the target, and the
    mechanistic wording in `docs/models_that_work.md` goes. A confirmatory fresh-set test with
    `macro_R` as primary metric would need a D-xxx (metric change).
  - inconclusive: the caveat stays as worded. Inconclusive is not equivalence: it shows neither
    that the lift is target-level nor that it is a design effect.
  - if C6 (primary) and C4 (secondary) disagree, both are reported and the caveat follows the more
    cautious of the two.
- primary comparison: none in the `grnbench report` sense (exploratory; the declared tests are T1,
  T2 and T3 above, computed by `motif_sensitivity.py report`).
- smallest effect that matters (margin): none declared. The 0.5 L thresholds of the decision rule
  are fixed now.
- exclusion rules (fixed now): (a) a dataset whose kept artifacts are missing (reference halves,
  `decisions.json`, at least one `processed.h5ad` per arm), or whose committed row lacks a
  stage-1 score, is reported and excluded; (b) a dataset failing gate 1 is reported and excluded;
  (c) a unit ending with a runtime error (anything but a failed code check: I/O, memory, a killed
  worker) is resubmitted once with the same commit, then reported and excluded if it still fails;
  a failed code check is not an exclusion but rule 0 above; (d) a dataset with no finite value for
  a test's metric (for example no TF with 5 positives in U'') leaves that test only, and n is
  printed per test; (e) nothing else: no outlier removal, no replacement. A missing run-folder
  row is a note, not an exclusion (gate 1 reads the committed row).
- seeds: keyed permutation seeds 0-99; bootstrap seed 0. Inherited from the registered runs and already
  applied in the kept files: reference split seed 0, cell subsample seed 0 (at most 3,000 cells),
  150 regulators (`MAX_TFS`). Pearson has no seed.

## 2. How it runs

- data and provenance (nothing new is downloaded except the registered cisTarget files if GB's
