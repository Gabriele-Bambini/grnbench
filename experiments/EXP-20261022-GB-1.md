  by `real_bench` (`metrics.evaluate_ranking`) in C4.

  EXP-20261003-GB-1 (stage 1, Pearson, from the kept artifacts; gates 1 and 2 as in that record).
  Family: T3 in both directions = 2 directed hypotheses, Holm, alpha 0.05; **supported** if p_Holm(real >
  gene_tf) < 0.05, **refuted** if p_Holm(gene_tf > real) < 0.05, otherwise inconclusive. It does not
  change H1's family. Planning only: the SD of the T3 differences in stage 1 was about 0.21 (C6 and C4,
  n = 20 each), so n = 120 detects about +0.054 macro_R with 80% power (one-sided, alpha/2). Running it

  alpha 0.05, as printed by `real_bench.py report`. **H1 is supported** if p_Holm(pearson_motif >
  pearson_signed) < 0.05; **refuted** if p_Holm(pearson_signed > pearson_motif) < 0.05; otherwise

- primary comparison: pearson_motif > pearson_signed | epr | auto

  n = 120 and 0.797 at n = 100 for +0.10 (one-sided, alpha/2); smallest effect detectable with 80%

  the observed SD.
- seeds: reference split seed 0 (`screen.split_reference`), cell subsample seed 0 (at most 3,000 cells
  per context, `engine_bench.MAX_SCORE_CELLS`), scrublet seed 0; regulators = the 150 TFs with most

## 2. How it runs

- code: branch `gb/pool-200`, synced to a separate cluster checkout `~/grnbench-pool200` with
  `hpc/hpc.sh sync`; the job copies `GIT_COMMIT` into the results as `CODE_COMMIT`. The commit that
  runs is the one that adds the data snapshot (below), pushed before any model runs; `real_bench.py`
  and the engine are `main`'s (6917c88), the branch adds only the selection tools and records.
- environment: conda env `grnbench` on the cluster, Python 3.11, `requirements/lock-py311.txt`; no
  extra packages (no torch).
- storage: a dedicated data folder `~/grnbench_pool200` (a link into `~/projects/grnbench/`), outside
  the code checkout; run folders in `~/gb_runs`, temporary files in `~/gb_tmp`. LD's review asked for the
  cluster's large scratch area; on 2026-10-23 that area gave `Remote I/O error` on every file write for
  this account, and the cluster's `lquota` reports no limit on home (limit shown as infinite), so the
  data stay in home. Task files written by `real_bench.py plan` contain absolute cluster paths, so only
  portable copies (paths relative to the data root) are committed.
- data (login node, downloads and checks only; `R=~/grnbench_pool200/refs`,
  `D=~/grnbench_pool200/confirmatory`):
  ```
  python benchmarks/fetch_cellxgene.py --out $D/cellxgene --from-manifest experiments/EXP-20261022-GB-1.datasets.tsv
  python benchmarks/data_manifest.py $R --check experiments/EXP-20261022-GB-1.snapshot.tsv --require-all   # must exit 0
  python benchmarks/data_manifest.py $D > experiments/EXP-20261022-GB-1.data.tsv     # committed and pushed before any model runs
  python benchmarks/data_manifest.py $D --check experiments/EXP-20261022-GB-1.data.tsv --require-all   # must exit 0 at launch
  ```
  The data snapshot must hold exactly the 120 datasets' `data.h5ad` and `truth.json` (240 files). Every
  copy is made with `--from-manifest`, so every copy has the same `README.md` (title only).
- pilot (time and memory only, before the main job): `real_bench.py` with this record's models and
  `candidate_study.py` (condition `clean`), one worker each, on three datasets of the **exploratory**
  part fixed now: the largest file (`10x-3-v3/homo-sapiens/retinal-pigment-epithelial-cel__a41fb1c7`,
  1,843 MB), the most cells (`10x-multiome/homo-sapiens/brain__0b024b1e`, 215,680 cells) and the median
  file (`10x-3-v3/homo-sapiens/tendon-of-quadriceps-femoris__acd544d0`, 316 MB). Its scores are deleted
  unread; it only sets the number of parallel workers (`JOBS`), the memory and the expected time. No
  confirmatory dataset is touched by the pilot. The largest confirmatory dataset (495,763 cells) is
  larger than any pilot dataset; if it runs out of memory, rule (e) applies.
- commands (`O=~/gb_runs/EXP-20261022-GB-1`; QOS `stud`, 8 CPUs, 24 h, memory from the pilot):
  ```
  python benchmarks/real_bench.py plan --data-root $D --out $O/real_tasks.json
  sbatch --time=24:00:00 --mem=<from the pilot> --export=ALL,REPO_DIR=$HOME/grnbench-pool200,OUT=$O,SCRIPT=benchmarks/real_bench.py,TASKS=$O/real_tasks.json,REFS=$R/references,CHUNK=100000,JOBS=<from the pilot>,MODELS=pearson_signed+pearson_motif,KEEP_ARTIFACTS=1,GRNBENCH_CISTARGET_DIR=$R/cistarget,TMPDIR=$HOME/gb_tmp hpc/engine_bench.sbatch
  python benchmarks/real_bench.py report --out $O --tasks-for-viz $O/real_tasks.json
  grnbench viz $O ; grnbench report $O
  ```
  `JOBS` changes only the speed: every dataset is processed alone with fixed seeds. Unfinished datasets
  are resumed by one resubmission of the same commit (exclusion rule e).
- machine: Bocconi HPC, partition/QOS `stud` (1 running + 1 queued job per user), 8 CPUs, 24 h per job.
- results: `benchmarks/results/EXP-20261022-GB-1/` (rows, report, portable task file, figures within the
  size rule); edges, processed data and kept artifacts stay in `$O` (they also allow T3 and the EPR
  diagnosis of step 15-2 on this set later).
- report input: `benchmarks/results/EXP-20261022-GB-1`.
- status at registration: no dataset of the list scored.
- status at launch (2026-10-23): all 120 datasets fetched with `--from-manifest` into the data folder;
  sha256 of their 240 files (`data.h5ad`, `truth.json`; exactly the list) in
  `experiments/EXP-20261022-GB-1.data.tsv`; references and cisTarget checked against the snapshot
  (ok=8, MISMATCH=0, MISSING=0). No model has run on any of them. The run commit is the one that adds
  this line.
