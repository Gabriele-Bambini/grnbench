# EXP-20261003-LM-1: Without a reference, is the fixed baseline better than the engine's choice? With one, does screening gene-set-preserving candidates beat the baseline?

## 1. Registration (before the run)

- type: **confirmatory** (pre-registration = the commit that adds this file, pushed before the
  job starts)
- owner: LM (agent-run)   issue: #36   registered: 2026-10-03
- follows: EXP-20261002-LM-2 (exploratory candidate study, 20 datasets x 7 degradations, the
  development set). There, without a reference the engine's choice lost to the fixed baseline in
  every condition (clean: -0.124 AUPRC ratio, 95% interval [-0.212, -0.035]), and with the
  reference, choosing among candidates that keep the baseline's gene set gained +0.019
  [+0.002, +0.036] on clean data. Choosing among all candidates gained more (+0.044), but about
  70% of that came from candidates that change the gene set (mostly `hvg=tf_plus_2000`) and are
  therefore scored on a different TF x gene universe; they are left out of this test.
- decision this informs: D-021 (proposed in #34): without a reference the engine returns the
  baseline; with one, it screens gene-set-preserving candidates.
- hypotheses (co-primary, directional), condition `clean`:
  H1: the fixed baseline (`engine_bench.BASELINE`) recovers the CollecTRI evaluation half better
  than the shipped reference-free choice (`rank_candidates` without reference columns over the
  engine's candidates and the baseline: edge stability - depth leakage - batch leakage).
  H2: the reference-based choice among gene-set-preserving candidates (highest selection-half
  AUPRC ratio among candidates whose `hvg` and `gene_filter` equal the baseline's: the engine's
  own, the baseline and its one-change variants) recovers it better than the baseline.
- primary endpoint: `eval_mean` = AUPRC ratio on the CollecTRI evaluation half, mean of
  pearson_signed, spearman_signed and clr (`engine_bench.EVAL_METHODS`), as in the earlier runs.
- secondary (reported, not used for H1/H2): the same two comparisons in conditions `doublets_20`
  and `damaged_15`; the full `SUMMARY.md` of `candidate_study.py report`.
- unit of analysis: dataset. Planned n = 20 per condition.
- datasets: the 20 CELLxGENE datasets of EXP-20261002-LM-1 (`EXP-20261002-LM-1.datasets.tsv`,
  sha256 in `experiments/datasets.tsv`, `~/grnbench_data_fresh1`). They were used only to test
  the motif prior (C6); no selection rule or engine default was developed or tuned on them.
- reference: the registered CollecTRI snapshot (same bytes as EXP-20261002-LM-2), so the two
  studies differ only in datasets (D-020: a test of rules developed on registered data keeps the
  registered reference).
- exclusion rules (fixed now): (a) data failing `data_manifest.py --check` stops the run;
  (b) datasets with fewer than 50 reference edges are not scored; (c) a dataset where either arm
  of a pair has no score (QC gate refusal or error) is left out of that pair, and the number left
  out is reported; (d) a task still missing after the job and one resubmission is reported as
  missing; (e) no other exclusion.
- comparison family: `candidate_study.CONFIRM_FAMILY` = {(baseline, noref_shipped),
  (ref_geneset_preserving, baseline)}, both directions = 4 directed hypotheses per condition.
- test: paired t over datasets via `compare_units`, two-sided per direction, Holm over the 4
  directed hypotheses of the condition, alpha 0.05 (`candidate_study.py confirm`). For each of
  H1, H2: **supported** if p_Holm(A > B) < 0.05 as stated; **refuted** if p_Holm(B > A) < 0.05;
  otherwise inconclusive (not evidence of equality).
- primary comparison: baseline > noref_shipped | eval_mean | clean; ref_geneset_preserving > baseline | eval_mean | clean
- smallest effect that matters: none declared.
- seeds: degradation seed 0; reference split seed 0; the adapters' default seeds.

## 2. How it runs

- code: branch `lm/candidate-study` at the commit that adds this file (`candidate_study.py` with
  `CONFIRM_FAMILY` and `confirm`). Synced to a separate cluster checkout `~/grnbench-cs3`; the job
  copies `GIT_COMMIT` into the results as `CODE_COMMIT`.
- environment: conda env `grnbench`, Python 3.11, `requirements/lock-py311.txt`.
- commands (`D=~/grnbench_data_fresh1`, `O=~/gb_runs/EXP-20261003-LM-1`):
  ```
  python benchmarks/data_manifest.py $D --check experiments/datasets.tsv          # must exit 0
  python benchmarks/candidate_study.py plan --data-root $D --out $O/tasks.json --conditions clean,doublets_20,damaged_15
  sbatch --time=24:00:00 --export=ALL,REPO_DIR=$HOME/grnbench-cs3,OUT=$O,SCRIPT=benchmarks/candidate_study.py,TASKS=$O/tasks.json,REFS=$D/references,CHUNK=100000,JOBS=6,TMPDIR=$HOME/gb_tmp_cs3 hpc/engine_bench.sbatch
  python benchmarks/candidate_study.py report --out $O
  python benchmarks/candidate_study.py confirm --out $O
  ```
  `JOBS=6` leaves memory headroom (one worker of EXP-20261002-LM-2 was OOM-killed at 8). A killed
  worker now ends the job (`BrokenProcessPool`), and a resubmission resumes the missing tasks.
- machine: Bocconi HPC, QOS `stud`, 8 CPUs, 32 GB, 24 h; 60 tasks, about 6-10 h expected.
- results: `benchmarks/results/EXP-20261003-LM-1/` (rows, `SUMMARY.md`, `CONFIRM.md`).
- pre-launch correction (2026-10-03, nothing had run): the first submission (job 681174) was
  cancelled while still pending, because `data_manifest.py --check` gave `UNLISTED=40`: this branch
  predated #31, which registered the 20 datasets' hashes. `main` was merged into the branch and the
  run uses the merge commit. Besides the dataset rows, the merge brings engine fixes the development
  study (EXP-20261002-LM-2) did not have: #32 (a context that cannot be screened fails its
  candidate instead of the whole task; strategies may not emit NaN; ComBat drops one-cell batches)
  and #33 (raw-droplet state kept through screening; case-only duplicate genes merged, none in these
  datasets). They change results only where a context failed or crashed before; the analysis code
  (`candidate_study.py`, `CONFIRM_FAMILY`) is unchanged by the merge.
- pre-launch correction 2 (2026-10-03, nothing had run): job 681190 exited after 10 s with
  `unrecognized arguments: --max-attempts 2` (the sbatch from `main`, #29, always passes it) and
  wrote 0 rows. `candidate_study.py run` now accepts the flag and ignores it; no analysis code changed.
- launch deviation (2026-10-03, nothing scored): job 681196 started and every task it reached
