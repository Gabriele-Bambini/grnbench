# EXP-20261004-LM-2: From a raw droplet matrix, does the engine reach the recovery of the vendor-filtered matrix?

## 1. Registration (before the run)

- type: **exploratory** (8 datasets; descriptive, no p-values).
- owner: LM (agent-run)   issue: #51   data: #50   registered: 2026-10-04
- why: on curated, already-filtered matrices no cleaning change beats the fixed baseline by more
  than about 0.01 on shared genes (EXP-20261004-LM-1), so the engine's value there is avoiding
  harm. Raw droplet matrices are where cleaning should matter: empty droplets, ambient RNA and
  doublets are still in them. A one-dataset smoke (pbmc_1k_v2) gave: knee cell calling found 998
  cells from the raw matrix (10x's filtered matrix holds 996), and the baseline-from-raw AUPRC ratio
  was 1.362 against 1.358 from the filtered matrix. Without cell calling every pipeline was refused
  by the QC gates.
- question: per dataset, (a) does the engine produce a scored network from the raw matrix at all;
  (b) the AUPRC ratio of the engine's choice from the raw matrix minus the baseline's from 10x's
  filtered matrix (the vendor's own cell calls), on each arm's own universe and on shared genes;
  (c) which single cleaning change moves recovery on raw input (variant table, raw vs filtered).
- datasets: the 8 public 10x Genomics datasets of #50 (`benchmarks/fetch_10x_raw.py`): pbmc_1k_v3,
  pbmc_10k_v3, 5k_pbmc_protein_v3, pbmc_1k_v2 (human); neuron_1k_v3, neuron_10k_v3, heart_1k_v3,
  heart_10k_v3 (mouse). Raw and filtered `feature_bc_matrix.h5` each; sha256 into
  `experiments/datasets.tsv` before the run. pbmc_1k_v2 was used for the smoke test above (not a
  result).
- tasks: `candidate_study.py`, condition `clean` (no added degradation), one task per matrix
  (16 tasks). The raw matrix carries `raw_droplets` so the selector chooses cell calling; the
  filtered matrix does not.
- arms (fixed now): raw-engine = `engine_auto` (selection-half rule) on the raw task; raw-baseline =
  `baseline` on the raw task (inherits the selector's cell calling); filtered-baseline = `baseline`
  on the filtered task. Endpoint: `eval_mean` (AUPRC ratio on the CollecTRI evaluation half, mean
  of pearson_signed, spearman_signed, clr), plus the shared-gene pair fields.
- reference: the registered CollecTRI snapshot (human/mouse).
- exclusions: datasets with fewer than 50 reference edges are not scored; no other exclusion.
- seeds: reference split seed 0; adapter defaults.

## 2. How it runs

- code: branch `lm/raw10x` at the commit that adds this file; separate cluster checkout
  `~/grnbench-raw`; `CODE_COMMIT` copied into the results.
- data (login node, downloads only; `D=~/grnbench_data_raw10x`):
  ```
  python benchmarks/fetch_10x_raw.py --out $D/raw10x
  cp -r ~/grnbench_data_lm1/references $D/
  python benchmarks/data_manifest.py $D > /tmp/raw10x.tsv     # rows added to experiments/datasets.tsv
  python benchmarks/data_manifest.py $D --check experiments/datasets.tsv   # must exit 0 before submit
  ```
- commands (`O=~/gb_runs/EXP-20261004-LM-2`):
  ```
  python benchmarks/candidate_study.py plan --data-root $D --out $O/tasks.json --conditions clean
  sbatch --time=24:00:00 --export=ALL,REPO_DIR=$HOME/grnbench-raw,OUT=$O,SCRIPT=benchmarks/candidate_study.py,TASKS=$O/tasks.json,REFS=$D/references,CHUNK=100000,JOBS=4,TMPDIR=$HOME/gb_tmp_raw hpc/engine_bench.sbatch
  python benchmarks/candidate_study.py report --out $O
  ```
  `JOBS=4`: raw matrices of the 10k datasets are large in memory.
- results: `benchmarks/results/EXP-20261004-LM-2/`.

- reading (exploratory, 8 datasets):
  1. On 7 of 8 datasets the engine's knee cell calling recovered 0.95-1.00x Cell Ranger's cell
     count from the raw matrix. On 6 of them its network recovered the CollecTRI evaluation half
     within -0.028 to +0.014 of the baseline on the vendor-filtered matrix; the seventh,
     heart_1k_v3, is +0.124 through a gene-set-changing pick scored on a different edge universe
     (EXP-20261004-LM-1).
     Without cell calling, the same raw matrix is refused by the QC gates (smoke test, section 1).
  2. heart_10k_v3 failed: knee calling took 92,106 barcodes for 7,713 cells, the baseline was
     refused, and the engine's pick recovered 1.110 against 1.396. Cause: the knee search went
     down to 10 UMIs, so the steepest drop of the barcode-rank curve was the ambient-to-empty
     cliff (about 75 -> 8 UMIs), not the cell cliff.
- engine fix after the run (not part of the registered run): `knee_cell_threshold` now ignores
  barcodes under 100 UMIs, DropletUtils' `barcodeRanks` default (`lower = 100`), which its
  docstring already claimed to follow. On all 8 raw matrices it then calls 0.93-1.03x Cell Ranger's
  count (heart_10k_v3: 7,166; `knee_floor_check.txt`). A test built from heart_10k_v3's barcode-rank curve fails with the
  old floor. Follow-up rerun of the heart_10k_v3 raw task only, code 98ab16d (Slurm job 681701):
  7,166 cells; baseline 1.323, engine pick 1.342, against 1.396 on the filtered matrix
  (`postfix_heart_10k/SUMMARY.md`). Heart remains the hardest case (-0.073 for the baseline), but
  it is no longer a failure.
- deviations from section 1: the follow-up rerun above is outside the registered design and is
  reported separately; the registered rows are unchanged.
